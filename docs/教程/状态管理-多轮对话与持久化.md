## 1. Agent 为什么默认无状态

> **预计时间**：3 分钟

pydantic-ai 的 Agent 是无状态的——每次 `run()` 或 `run_stream()` 是独立的调用：

```python
# 每次调用都是"新对话"
await agent.run("天气怎么样")
await agent.run("那明天呢")  # Agent 不知道"那"指什么
```

**设计原因**：无状态 Agent 更容易测试、更容易水平扩展、更容易控制上下文大小。状态管理交给调用方，框架不替你做决定。

要实现多轮对话，只需要记住两个 API：

| API | 返回 | 用途 |
|-----|------|------|
| `result.new_messages()` | `list[ModelMessage]` | 仅本轮新增的消息 |
| `result.all_messages()` | `list[ModelMessage]` | 包含所有历史轮次的消息 |

```
第一轮 run()
  └── result1.all_messages()  = [request1, response1]
  └── result1.new_messages()  = [request1, response1]   ← 第一轮，没有历史

第二轮 run(message_history=result1.new_messages())
  └── result2.all_messages()  = [request1, response1, request2, response2]
  └── result2.new_messages()  = [request2, response2]   ← 只有本轮新增
```

**练习：**

1. 运行两次 `agent.run("北京天气")` 和 `agent.run("那明天呢")`，观察 Agent 是否知道"那"指什么
2. 打印 `result.all_messages()` 和 `result.new_messages()`，理解两者在第一轮和第二轮的差异

**验收标准：**

- [ ] 你能解释为什么 Agent 默认无状态
- [ ] 你能区分 `all_messages()` 和 `new_messages()` 的行为

## 2. message_history：多轮对话

> **预计时间**：15 分钟

每轮结束时，用 `result.new_messages()` 获取本轮新增的消息，下一轮通过 `message_history` 传入。

### 2.1 非流式版本

```python
from pydantic_ai import Agent

agent = Agent(
    'openai:gpt-5.2',
    instructions='Be a helpful assistant. Reply in Chinese.',
)

# 第一轮
result1 = agent.run_sync("北京三日游怎么安排？")
print(result1.output)

# 第二轮：传入上一轮的消息
result2 = agent.run_sync(
    "加点亲子景点",
    message_history=result1.new_messages(),
)
print(result2.output)
```

**发生的流程**：

```
第一轮                   第二轮
  │                        │
  result1.run_sync()       result2.run_sync(
  │                          "加点亲子景点",
  └── new_messages()         message_history=result1.new_messages()
       = [request1,          )
         response1]            │
                               ├── 组装 messages:
                               │     [request1, response1,  ← 来自历史
                               │      request2("加点亲子景点")]
                               │
                               └── LLM 看到完整上下文，知道"亲子景点"是
                                   在"北京三日游"的基础上追加
```

### 2.2 流式版本（run_stream_events）

教程的 `01.py` 和 `02.py` 用的是 `run_stream_events()`，这里统一用它：

```python
run_result = None

async with agent.run_stream_events(user_input, message_history=history) as events:
    async for event in events:
        if event.event_kind == "part_delta":
            delta = event.delta
            kind = getattr(delta, "part_delta_kind", None)
            if kind in ("text", "thinking"):
                content = getattr(delta, "content_delta", None)
                if content:
                    print(content, end="", flush=True)

        elif event.event_kind == "agent_run_result":
            run_result = event.result  # 流结束，保存 result

# ⚠️ 必须在 async with 块外面访问 new_messages()
if run_result:
    history.extend(run_result.new_messages())
```

### ⚠️ 流式关键坑

**流结束前，`new_messages()` 不包含 assistant 回复**，只有 `ModelRequest`（用户 prompt）部分：

```python
# ❌ 错误：在 async with 块内访问
async with agent.run_stream_events("hello") as events:
    async for event in events:
        if event.event_kind == "agent_run_result":
            print(event.result.new_messages())   # 不完整！没有 ModelResponse

# ✅ 正确：在 async with 块结束后访问
run_result = None
async with agent.run_stream_events("hello") as events:
    async for event in events:
        if event.event_kind == "agent_run_result":
            run_result = event.result

# 流已结束，消息完整
if run_result:
    print(run_result.new_messages())  # 包含完整的 ModelRequest + ModelResponse
```

### 2.3 result 中的消息 API

`run_stream_events()` 的 result 出现在 `agent_run_result` 事件中（`event.result`）。
常用的属性：

| 属性/方法 | 类型 | 说明 |
|-----------|------|------|
| `event.result.output` | `str` | LLM 的最终回复文本 |
| `event.result.new_messages()` | `list[ModelMessage]` | 本轮新增消息 |
| `event.result.all_messages()` | `list[ModelMessage]` | 所有历史消息 |
| `event.result.usage` | `RunUsage` | token 消耗统计 |

完整的两轮对话：

```python
from pydantic_ai import Agent

agent = Agent('openai:gpt-5.2', instructions='Be a helpful assistant. Reply in Chinese.')

history = []

# 第一轮
async with agent.run_stream_events("北京三日游怎么安排？", message_history=history) as events:
    async for event in events:
        if event.event_kind == "part_delta":
            delta = event.delta
            kind = getattr(delta, "part_delta_kind", None)
            if kind in ("text", "thinking"):
                content = getattr(delta, "content_delta", None)
                if content:
                    print(content, end="", flush=True)
        elif event.event_kind == "agent_run_result":
            history.extend(event.result.new_messages())

# 第二轮
async with agent.run_stream_events("加点亲子景点", message_history=history) as events:
    async for event in events:
        if event.event_kind == "part_delta":
            delta = event.delta
            kind = getattr(delta, "part_delta_kind", None)
            if kind in ("text", "thinking"):
                content = getattr(delta, "content_delta", None)
                if content:
                    print(content, end="", flush=True)
        elif event.event_kind == "agent_run_result":
            history.extend(event.result.new_messages())
```

**练习：**

1. 用 `message_history` 实现两轮对话：先问"推荐北京景点"，再问"有哪些免费的"
2. 在 `async with` 块内和块外分别打印 `event.result.output`，确认块内为 `None`
3. 不传 `message_history`，运行同样对话，确认 Agent 不知道上下文

**验收标准：**

- [ ] 你能用 `message_history` 实现多轮对话
- [ ] 你知道流式场景中 `new_messages()` 必须在 `async with` 块外面访问

**常见错误：**

1. **在流结束前访问 `new_messages()`**：返回不完整的消息，缺少 assistant 回复
2. **把 `all_messages()` 当 `new_messages()` 用**：每轮都传入全量历史会导致消息列表越来越长
3. **忘记 `message_history` 非空时不生成系统提示词**：见 5.2 节的解决方案

## 3. ModelMessagesTypeAdapter：官方序列化方案

> **预计时间**：10 分钟

前面把消息存在 `history: list[ModelMessage]` 里，一关程序就没了。pydantic-ai 提供 `ModelMessagesTypeAdapter`——`list[ModelMessage]` 的官方 `TypeAdapter`，是消息持久化的唯一推荐方式。

> 官方文档：[Message History](https://pydantic.dev/docs/ai/core-concepts/message-history/)

### 3.1 完整序列化/反序列化

下面的例子用一个 JSON 文件来模拟"磁盘存储"——从文件读写，而不是从数据库。这让你先理解序列化本身，数据库的部分在 Section 4。

```python
import json
from pathlib import Path
from pydantic_ai import Agent, ModelMessagesTypeAdapter
from pydantic_core import to_jsonable_python, to_json

agent = Agent('openai:gpt-5.2', instructions='Be a helpful assistant.')

# ═══════════════════════════════════════════════════════════
# ── 第一轮：跑完 → 序列化 → 存到文件 ──
# ═══════════════════════════════════════════════════════════
result1 = agent.run_sync('Tell me a joke.')
history = result1.all_messages()  # list[ModelMessage]

# 方式一：to_jsonable_python → 存入文件（模拟 JSONB 列）
as_python_objects = to_jsonable_python(history)
Path("history.json").write_text(
    json.dumps(as_python_objects, ensure_ascii=False),
    encoding="utf-8",
)

# 方式二：to_json → 直接写入文件（模拟 VARCHAR 列）
Path("history.bin").write_bytes(to_json(history))

# ═══════════════════════════════════════════════════════════
# ── 从文件读取 → 反序列化 → 传入下一轮 ──
# ═══════════════════════════════════════════════════════════

# 方式一的反序列化
raw = json.loads(Path("history.json").read_text(encoding="utf-8"))
restored = ModelMessagesTypeAdapter.validate_python(raw)

# 方式二的反序列化
restored = ModelMessagesTypeAdapter.validate_json(Path("history.bin").read_bytes())

# ── 第二轮：用恢复的历史继续对话 ──
result2 = agent.run_sync('Tell me a different joke.', message_history=restored)
print(result2.output)
```

### 3.2 两种方式的选择

| 方式 | 函数 | 输出 | 适用场景 |
|------|------|------|---------|
| Python 对象 | `to_jsonable_python(history)` | `list[dict]` | PostgreSQL JSONB、MongoDB |
| JSON bytes | `to_json(history)` | `bytes` | 文件存储、Redis、VARCHAR 列 |

### 3.3 底层原理

```python
from pydantic import TypeAdapter
from pydantic_ai import ModelMessage

ModelMessagesTypeAdapter = TypeAdapter(list[ModelMessage])
```

它使用 discriminated union（`kind` 和 `part_kind` 字段）精确重建类型，保证序列化后类型信息不丢失。

**练习：**

1. 运行一个两轮对话，把 `all_messages()` 序列化为 JSON，检查 JSON 中的 `kind` 字段
2. 用 `validate_python()` 从 JSON 恢复消息，作为 `message_history` 传入下一轮

**验收标准：**

- [ ] 你能用 `ModelMessagesTypeAdapter` 完成消息的序列化和反序列化
- [ ] 你理解 `to_jsonable_python` 和 `to_json` 分别适用于什么场景

**常见错误：**

1. **直接 `json.dumps(history)`**：`ModelMessage` 对象不能直接 JSON 序列化，必须先用 `to_jsonable_python()` 转换
2. **自己手写序列化逻辑**：`ModelMessage` 结构可能随版本变化，必须用官方 `ModelMessagesTypeAdapter`

## 4. 持久化实战

> **预计时间**：20 分钟

这一节给出三个完整可运行的持久化方案，从简单到生产级，逐层递进。

### 4.1 文件版：JSON 文件存储

适合脚本、CLI 工具、单机 demo。

```python
import json
from pathlib import Path

from pydantic_ai import Agent, ModelMessagesTypeAdapter, ModelMessage
from pydantic_core import to_jsonable_python


class FileConversation:
    """基于 JSON 文件持久化的对话管理"""

    def __init__(self, agent: Agent, file_path: str = "conversation.json"):
        self.agent = agent
        self.file_path = Path(file_path)
        self.messages: list[ModelMessage] = []

    def load(self) -> "FileConversation":
        """从 JSON 文件恢复对话历史"""
        if self.file_path.exists():
            raw = json.loads(self.file_path.read_text(encoding="utf-8"))
            self.messages = ModelMessagesTypeAdapter.validate_python(raw)
        return self

    def save(self) -> None:
        """将对话历史保存到 JSON 文件"""
        data = to_jsonable_python(self.messages)
        self.file_path.write_text(
            json.dumps(data, ensure_ascii=False), encoding="utf-8"
        )

    async def chat(self, user_input: str) -> str:
        full_reply = ""
        async with self.agent.run_stream(
            user_input, message_history=self.messages,
        ) as result:
            async for text in result.stream_text():
                print(text, end="", flush=True)
                full_reply += text

        self.messages.extend(result.new_messages())
        print()
        return full_reply


# 使用
async def main():
    agent = Agent("openai:gpt-5.2", instructions="Reply in Chinese.")
    conv = FileConversation(agent, "chat_history.json").load()
    await conv.chat("北京三日游怎么安排？")
    await conv.chat("加点亲子景点")
    conv.save()
```

### 4.2 SQLite：JSON 列存储

适合轻量级本地应用，不需要单独部署数据库。

```python
import json
import sqlite3

from pydantic_ai import Agent, ModelMessagesTypeAdapter
from pydantic_core import to_jsonable_python


class SQLiteConversation:
    """基于 SQLite 持久化的对话管理"""

    def __init__(self, agent: Agent, session_id: str, db_path: str = "chat.db"):
        self.agent = agent
        self.session_id = session_id
        self.conn = sqlite3.connect(db_path)
        self._init_table()
        self.messages = self._load()

    def _init_table(self):
        self.conn.execute("""
            CREATE TABLE IF NOT EXISTS conversations (
                session_id TEXT PRIMARY KEY,
                messages_json TEXT NOT NULL DEFAULT '[]'
            )
        """)
        self.conn.execute(
            "INSERT OR IGNORE INTO conversations (session_id) VALUES (?)",
            (self.session_id,),
        )
        self.conn.commit()

    def _load(self) -> list:
        row = self.conn.execute(
            "SELECT messages_json FROM conversations WHERE session_id = ?",
            (self.session_id,),
        ).fetchone()
        if row and row[0]:
            return ModelMessagesTypeAdapter.validate_python(json.loads(row[0]))
        return []

    def _save(self):
        data = to_jsonable_python(self.messages)
        self.conn.execute(
            "UPDATE conversations SET messages_json = ? WHERE session_id = ?",
            (json.dumps(data, ensure_ascii=False), self.session_id),
        )
        self.conn.commit()

    async def chat(self, user_input: str) -> str:
        full_reply = ""
        async with self.agent.run_stream(
            user_input, message_history=self.messages,
        ) as result:
            async for text in result.stream_text():
                print(text, end="", flush=True)
                full_reply += text

        self.messages.extend(result.new_messages())
        self._save()
        print()
        return full_reply
```

### 4.3 PostgreSQL + SQLAlchemy async：生产级

真实 Web 应用的标准方案。安装依赖：

```bash
pip install pydantic-ai sqlalchemy[asyncio] asyncpg
```

**核心设计**：消息不应该堆在一个 JSONB blob 里，应该单独一张表。

```
conversations          (会话元数据：id, title, created_at...)
  └── conversation_messages  (消息明细：role, content, created_at...)
```

好处：可查询（"所有用户消息"）、可分页（只取最近 N 条控制上下文）、可关联（每条消息可绑定到 run_id 追踪 token 消耗）。

**表结构**：

```python
import uuid
from datetime import datetime

from sqlalchemy import Column, DateTime, ForeignKey, Integer, String, Text, func
from sqlalchemy.dialects.postgresql import UUID
from sqlalchemy.orm import DeclarativeBase, relationship


class Base(DeclarativeBase):
    pass


class Conversation(Base):
    """会话容器：只存元数据，不存消息内容"""
    __tablename__ = "conversations"

    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    session_id = Column(String(128), unique=True, nullable=False, index=True)
    user_id = Column(UUID(as_uuid=True), nullable=False, index=True)
    title = Column(String(255), default="New Chat", nullable=False)
    created_at = Column(DateTime(timezone=True), server_default=func.now())
    updated_at = Column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now())

    messages = relationship("ConversationMessage", back_populates="conversation", order_by="ConversationMessage.id")


class ConversationMessage(Base):
    """消息明细表：每条消息一行，结构化查询 + 按需裁剪"""
    __tablename__ = "conversation_messages"

    id = Column(Integer, primary_key=True, autoincrement=True)
    conversation_id = Column(
        UUID(as_uuid=True),
        ForeignKey("conversations.id", ondelete="CASCADE"),
        nullable=False, index=True,
    )
    role = Column(String(16), nullable=False)   # 'user' | 'assistant'
    content = Column(Text, nullable=False)
    created_at = Column(DateTime(timezone=True), server_default=func.now())

    conversation = relationship("Conversation", back_populates="messages")
```

> 这是 5.3 节「方案 B」的落地版——消息存在结构化列里，写入和读取各做一次转换。
> 如果你不需要按 role 查询和分页，直接用 4.2 的 JSON blob 方案即可。

**完整的 ConversationService：**

```python
from typing import Optional
import json

from pydantic_ai import Agent, ModelMessage, ModelMessagesTypeAdapter
from pydantic_ai.messages import ModelRequest, ModelResponse, TextPart, UserPromptPart
from pydantic_core import to_jsonable_python
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession


class PostgresConversation:
    """PostgreSQL + SQLAlchemy async 持久化"""

    def __init__(self, agent: Agent, session_id: str, user_id: str, db: AsyncSession):
        self.agent = agent
        self.session_id = session_id
        self.user_id = user_id
        self.db = db
        self._conv_id: Optional[uuid.UUID] = None

    # ═══════ 读取端：DB 行 → ModelMessage ═══════

    @staticmethod
    def _build_history(rows) -> list[ModelMessage]:
        """将 conversation_messages 行转为 pydantic-ai 的 ModelMessage 列表"""
        history: list[ModelMessage] = []
        for row in rows:
            if row.role == "user":
                history.append(ModelRequest(parts=[UserPromptPart(content=row.content)]))
            elif row.role == "assistant":
                history.append(ModelResponse(parts=[TextPart(content=row.content)]))
        return history

    async def _load_history(self) -> list[ModelMessage]:
        """从 conversation_messages 表查询最近 N 条消息"""
        stmt = (
            select(ConversationMessage)
            .join(Conversation)
            .where(Conversation.session_id == self.session_id)
            .order_by(ConversationMessage.id.asc())
            .limit(50)  # 只取最近 50 条，控制上下文大小
        )
        result = await self.db.execute(stmt)
        return self._build_history(result.scalars().all())

    # ═══════ 写入端：用户消息 + assistant 回复 ═══════

    async def _save_user_message(self, content: str):
        conv_id = await self._ensure_conversation()
        self.db.add(ConversationMessage(
            conversation_id=conv_id,
            role="user",
            content=content,
        ))
        await self.db.commit()

    async def _save_assistant_message(self, content: str):
        conv_id = await self._ensure_conversation()
        self.db.add(ConversationMessage(
            conversation_id=conv_id,
            role="assistant",
            content=content,
        ))
        await self.db.commit()

    async def _ensure_conversation(self) -> uuid.UUID:
        """懒创建：只有第一条消息写入时才建 conversation 行"""
        if self._conv_id:
            return self._conv_id

        stmt = select(Conversation).where(Conversation.session_id == self.session_id)
        result = await self.db.execute(stmt)
        conv = result.scalar_one_or_none()

        if conv:
            self._conv_id = conv.id
        else:
            conv = Conversation(session_id=self.session_id, user_id=self.user_id)
            self.db.add(conv)
            await self.db.commit()
            await self.db.refresh(conv)
            self._conv_id = conv.id

        return self._conv_id

    # ═══════ 对话 ═══════

    def chat(self, user_input: str):
        """返回 async generator，适配 FastAPI StreamingResponse"""
        return self._chat_stream(user_input)

    async def _chat_stream(self, user_input: str):
        """发送消息，流式 SSE 输出，自动持久化到 conversation_messages"""
        # ① 加载历史（DB 行 → ModelMessage）
        message_history = await self._load_history()

        # ② 存用户消息（必须在 agent.run 之前）
        await self._save_user_message(user_input)

        # ③ 跑 agent，流式输出 SSE 事件
        full_reply = ""
        run_result = None

        async with self.agent.run_stream_events(
            user_input,
            message_history=message_history,
        ) as events:
            async for event in events:
                if event.event_kind == "part_delta":
                    delta = event.delta
                    kind = getattr(delta, "part_delta_kind", None)
                    if kind in ("text", "thinking"):
                        content = getattr(delta, "content_delta", None)
                        if content:
                            yield _sse("TEXT_MESSAGE_CONTENT", delta=content)
                            full_reply += content

                elif event.event_kind == "agent_run_result":
                    run_result = event.result

        # ④ 流结束后存 assistant 回复
        if full_reply:
            await self._save_assistant_message(full_reply)
            usage = run_result.usage if run_result else None
            yield _sse(
                "RUN_FINISHED",
                input_tokens=usage.input_tokens if usage else 0,
                output_tokens=usage.output_tokens if usage else 0,
            )
```

**FastAPI 路由中的使用：**

```python
from fastapi import APIRouter, Depends
from fastapi.responses import StreamingResponse
from sqlalchemy.ext.asyncio import AsyncSession

router = APIRouter()


@router.post("/chat/stream")
async def chat_stream(
    user_input: str,
    session_id: str,
    user_id: str = Depends(get_current_user_id),
    db: AsyncSession = Depends(get_db),
):
    agent = get_agent()

    conv = PostgresConversation(agent, session_id, user_id, db)

    return StreamingResponse(
        conv.chat(user_input),       # chat() 返回 async generator
        media_type="text/event-stream",
    )
```

**SSE 编码辅助：**

```python
def _sse(event_type: str, **kwargs) -> str:
    """与 02.py 一致的 SSE 编码"""
    payload = {"type": event_type, **kwargs}
    return f"data: {json.dumps(payload, ensure_ascii=False)}\n\n"
```

> **关键设计对比**：
> - 4.1 / 4.2 用 `ModelMessagesTypeAdapter` 存整个 `list[ModelMessage]` 到 JSON blob——**零转换，按 blob 粒度的增删改查**
> - 4.3 把消息拆到独立行——**`_build_history()` 行 → `ModelMessage`，写的时候分 user / assistant 两个时机 INSERT**
> - 两种方式都正确，选哪种取决于你是否需要 `WHERE role = 'user'` 这种查询（详见 5.3）

确认表已创建后，发送请求：

curl -X POST http://localhost:8000/chat/stream \

curl -X POST http://localhost:8000/chat/stream \

**练习：**

1. 运行 `FileConversation`，对话两轮后退出，重新加载确认历史恢复正确
2. 用 `SQLiteConversation` 实现多会话隔离：两个 session_id 各自独立
3. 给 `PostgresConversation` 的消息写入增加 `run_id` 字段，关联到 agent run 的 token 消耗统计

**验收标准：**

- [ ] 你能实现一个可持久化的对话管理类
- [ ] 你理解增量保存 (`new_messages`) 和全量快照 (`all_messages`) 的区别
- [ ] 你知道 `ModelMessagesTypeAdapter` 是反序列化的唯一正确方式

**常见错误：**

1. **自己写序列化而不是用 `to_jsonable_python`**：`ModelMessage` 对象结构复杂，手写容易漏字段
2. **流式场景中在 `async with` 块内保存**：此时 `new_messages()` 不完整
3. **SQLAlchemy JSONB 列用 `json.dumps`**：JSONB 类型直接接受 `list[dict]`，不需要手动 `json.dumps`
4. **StreamingResponse 传入非 async generator**：`chat()` 必须用 `yield` 返回 SSE 事件，不能直接 return 字符串

## 5. 生产环境架构决策

> **预计时间**：20 分钟

前四节构成了最小可用闭环：`message_history` → `new_messages()` → `ModelMessagesTypeAdapter` → 持久化。
但在真实项目中，你会撞到三个架构问题。本节逐一给出决策指南。

### 5.1 先建 session 还是先 run？

`conversation_id` 是 pydantic-ai v2 引入的跨轮次关联机制——框架在每次 `run()` 时自动生成 UUID，印在每条消息上。
传入 `message_history` 时自动继承，序列化时跟着消息一起持久化。

对于 Web 应用，问题是：session 先建还是 agent run 之后建？

**方式一：先 run，后提取（简单场景）**

```python
# 第一轮：不传 conversation_id，框架自动生成
result1 = agent.run_sync("你好")
cid = result1.conversation_id  # "a1b2c3d4-..." ← run 完才拿到
save_conversation_to_db(cid)   # 此时 DB 里才有记录

# 第二轮：message_history 自动继承同一个 ID
result2 = agent.run_sync("继续聊", message_history=result1.new_messages())
assert result2.conversation_id == cid  # ✅
```

**方式二：先建 session，再传入（Web 应用推荐）**

前端请求到达时先生成 session_id，写入 DB、返回前端，然后作为 `conversation_id` 传入第一轮 `agent.run()`：

```python
import uuid

# ① 前端请求到达 → 先生成 session
session_id = str(uuid.uuid4())
db.execute("INSERT INTO sessions (id, user_id, title) VALUES (?, ?, ?)",
           (session_id, user_id, "新对话"))

# ② 第一轮 agent.run — 用你自己的 ID
result1 = agent.run_sync("你好", conversation_id=session_id)
assert result1.conversation_id == session_id  # ✅

# ③ 后续轮次自动继承
result2 = agent.run_sync("继续聊", message_history=result1.new_messages())
assert result2.conversation_id == session_id  # ✅
```

**决策指南**：

```
你的系统有自己的 session/thread 概念吗？
├── 没有（脚本、CLI、demo）
│   └── 方式一。或不关心 conversation_id，只用 message_history。
│
└── 有（Web 应用、FastAPI、多用户）
    └── 方式二。好处：前端立即有 session_id，可做路由、权限、并发控制。
```

**对话分叉**：传入 `conversation_id="new"` 忽略历史中的 ID，生成新 UUID：

```python
# 同一段历史，两个独立分支
branch_a = agent.run_sync("时间复杂度？", message_history=history,
                          conversation_id="conv-001-branch-a")
branch_b = agent.run_sync("可读性优化？", message_history=history,
                          conversation_id="conv-001-branch-b")
```

### 5.2 系统提示词消失问题

当 `message_history` 非空时，pydantic-ai **不会重新生成系统提示词**。如果从数据库加载的历史里没有系统提示词，LLM 行为会不符合预期。

**解决**：加一个 `ReinjectSystemPrompt` capability：

```python
from pydantic_ai import Agent
from pydantic_ai.capabilities import ReinjectSystemPrompt

agent = Agent(
    "openai:gpt-5.2",
    instructions="Be a helpful assistant. Reply in Chinese.",
    capabilities=[ReinjectSystemPrompt()],
)

# message_history 非空也会重新注入 instructions
result = agent.run_sync("你好", message_history=loaded_history)
```

### 5.3 存储格式选型：JSON blob vs 独立的 messages 表

这是持久化架构中最关键的决策。两种方案本教程都给出了完整实现：

| 方案 | 代码位置 | 核心思路 |
|------|---------|---------|
| A：JSON blob | 4.2 SQLiteConversation | `list[ModelMessage]` → JSON 字符串 → 一行存整个对话 |
| B：独立的 messages 表 | 4.3 PostgresConversation | 每条消息一行 `(role, content)`，读写各做一次转换 |

**对比**：

| 维度 | A：JSON blob（4.2） | B：独立 messages 表（4.3） |
|------|---------------------|---------------------------|
| 存储格式 | `ModelMessagesTypeAdapter` JSON | `(role, content)` 结构化列 |
| 读写转换 | 零转换 | `build_history()` ← 行 → INSERT |
| 按 role 查询 | 需解析 JSON | `WHERE role = 'user'` |
| 分页 / 裁剪 | 解析 JSON 后操作 list | `ORDER BY id DESC LIMIT 20` |
| 单条消息引用 | 无法引用（blob 内部） | 每条有自增 id |
| 版本兼容 | `ModelMessagesTypeAdapter` 保证 | `build_history()` 自行跟进 |
| 适合场景 | 简单应用、脚本、demo | Web 应用、多用户、需查询 |

**怎么选**：

```
需要按 role 查询消息？或按 ID 关联消息到其他表？
├── 不需要 → 方案 A（4.2），零转换最省事
└── 需要   → 方案 B（4.3），代价是多维护一个 build_history() 函数
```

## 6. 速查表

| 场景 | API |
|------|-----|
| 获取本轮新增消息 | `result.new_messages()` |
| 获取所有历史消息 | `result.all_messages()` |
| 序列化为 Python 对象（JSONB） | `to_jsonable_python(messages)` |
