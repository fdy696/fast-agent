## 1. 什么是 Tool

> **本章目标**：理解 Tool 的概念及其在 Agent 中的作用
> **预计时间**：3 分钟

Tool（工具）是 Agent 与外部世界交互的桥梁。当 LLM 需要获取实时数据、执行计算、操作外部系统时，会通过工具调用完成。

```
用户: "北京天气怎么样？"
  │
  ▼
Agent
  ├── LLM 分析：需要查询天气
  ├── 调用 get_weather(city="北京")    ← 工具调用
  │     └── 返回 "晴 25°C"
  └── LLM 整合结果，回复用户
```

Pydantic AI 的工具注册有三种方式，按推荐优先级排列：

```
工具是在写代码时就知道的？
  ├── 是 → @agent.tool / @agent.tool_plain
  └── 否 → FunctionToolset 子类（见工程篇）
```

## 2. @agent.tool：带 RunContext 的工具

> **本章目标**：掌握用 `@agent.tool` 装饰器注册带上下文的工具
> **预计时间**：15 分钟

`@agent.tool` 是最常用的工具注册方式。装饰器从函数签名自动生成参数 schema。

```python
from pydantic_ai import Agent, RunContext
from pydantic_ai.models.openai import OpenAIChatModel
from pydantic_ai.providers.openai import OpenAIProvider
from openai import AsyncOpenAI
import asyncio

import ast
import operator as op

# 安全的数学计算器 — 白名单方式解析表达式
_SAFE_OPS = {
    ast.Add: op.add, ast.Sub: op.sub, ast.Mult: op.mul,
    ast.Div: op.truediv, ast.Pow: op.pow, ast.USub: op.neg,
}

def _safe_eval(expr: str) -> float:
    """安全地计算四则运算表达式。仅支持数字、+、-、*、/、**、()、空格。"""
    def _eval_node(node):
        if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
            return node.value
        if isinstance(node, ast.UnaryOp) and type(node.op) in _SAFE_OPS:
            return _SAFE_OPS[type(node.op)](_eval_node(node.operand))
        if isinstance(node, ast.BinOp) and type(node.op) in _SAFE_OPS:
            return _SAFE_OPS[type(node.op)](_eval_node(node.left), _eval_node(node.right))
        raise ValueError(f"不支持的运算: {ast.dump(node)}")
    return _eval_node(ast.parse(expr.strip(), mode='eval').body)


client = AsyncOpenAI(api_key="your-api-key", base_url="https://api.deepseek.com/v1")
model = OpenAIChatModel("deepseek-chat", provider=OpenAIProvider(openai_client=client))

agent = Agent(model=model, instructions="You are a helpful assistant. Reply in Chinese.")


@agent.tool
async def get_weather(ctx: RunContext, city: str) -> str:
    """获取指定城市的天气信息。

    Args:
        city: 城市名，例如 "北京" 或 "Shanghai"。
    """
    weather_data = {"北京": "晴 25°C", "上海": "多云 28°C"}
    return weather_data.get(city, f"未找到 {city} 的天气数据")


@agent.tool
async def calculate(ctx: RunContext, expression: str) -> str:
    """计算数学表达式。仅支持四则运算和括号。

    Args:
        expression: 数学表达式，例如 "2 + 3 * 4" 或 "(1 + 2) * 3"。
    """
    try:
        return str(_safe_eval(expression))
    except Exception as e:
        return f"计算错误: {e}"


async def main():
    result = await agent.run("北京天气怎么样？计算 25 + 17")
    print(result.data)


asyncio.run(main())
```

**关键原理**：
- `@agent.tool` 从函数签名自动生成参数 schema（`city: str` → LLM 看到"需要一个 string 类型的 city 参数"）
- docstring 的 `Args:` 部分会自动映射为参数描述——LLM 会看到每个参数的含义
- `ctx: RunContext` 永远是第一个参数（即使不用），框架通过它注入 Agent 状态

## 常见错误

1. **忘记 `ctx` 参数**：`@agent.tool` 修饰的函数必须把 `ctx: RunContext` 作为第一个参数
2. **docstring 写得太模糊**：LLM 靠描述决定是否调用，"获取天气" 不如 "获取指定城市的当前天气，参数 city 为城市名称"
3. **返回类型不明确**：统一返回 `str` 会让 LLM 和处理代码难以区分返回值含义

## 3. @agent.tool_plain：纯函数工具

> **本章目标**：掌握用 `@agent.tool_plain` 注册无状态工具
> **预计时间**：5 分钟

当工具不需要访问 Agent 状态时，用 `@agent.tool_plain` 更简洁——不需要 `ctx` 参数。

```python
from datetime import datetime
from pydantic_ai import Agent
from pydantic_ai.models.openai import OpenAIChatModel
from pydantic_ai.providers.openai import OpenAIProvider
from openai import AsyncOpenAI
import asyncio

client = AsyncOpenAI(api_key="your-api-key", base_url="https://api.deepseek.com/v1")
model = OpenAIChatModel("deepseek-chat", provider=OpenAIProvider(openai_client=client))

agent = Agent(model=model, instructions="You are a helpful assistant. Reply in Chinese.")


@agent.tool_plain
async def current_time() -> str:
    """获取当前服务器时间。"""
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")


@agent.tool_plain(retries=2)
async def get_user_count() -> int:
    """获取当前在线用户数。"""
    return 42


async def main():
    result = await agent.run("现在几点了？在线用户有多少？")
    print(result.data)


asyncio.run(main())
```

**与 `@agent.tool` 的区别**：不需要 `ctx: RunContext` 参数。适用于纯工具函数，不依赖 Agent 状态。

## 4. 工具参数 schema 与 docstring 最佳实践

> **本章目标**：写出 LLM 能准确理解并正确调用的工具描述
> **预计时间**：5 分钟

LLM 靠工具描述决定是否调用。描述要包含**什么时候用**和**参数含义**：

```python
# ❌ 描述太模糊
@agent.tool
async def search(ctx: RunContext, q: str) -> str:
    """搜索"""
    ...

# ✅ 清晰的描述
@agent.tool
async def search_users(ctx: RunContext, name: str) -> str:
    """根据姓名搜索用户。当需要查找特定用户信息时使用。

    Args:
        name: 用户的姓名或姓名的一部分，支持模糊匹配。
    """
    ...
```

**最佳实践清单：**

1. **docstring 功能描述**：说明工具做什么、什么时候用。LLM 靠这个决定是否调用
2. **`Args:` 参数描述**：写清楚每个参数的类型、格式、取值范围
3. **参数名用英文**：LLM 对英文参数名理解更稳定
4. **返回类型明确**：`-> str`、`-> int` 等，不要都返回 `-> Any`

## 常见错误

1. **docstring 太长**：LLM 上下文有限，描述控制在 1-3 句话
2. **不写 `Args:`**：即使 Python 函数能跑，LLM 看不到参数含义会随机传值
3. **返回类型全是 `-> Any`**：弱化类型信息，LLM 更难判断工具返回值格式

## 5. retries 与 ModelRetry

> **本章目标**：掌握框架内置的重试机制和 ModelRetry 用法
> **预计时间**：8 分钟

### retries 参数

### retries 参数

框架内置了重试机制。不要自己实现重试逻辑：

```python
# ❌ 不要自己实现重试
@agent.tool
async def unstable_api(ctx: RunContext) -> str:
    for i in range(3):  # 手写重试
        try:
            return await call_api()
        except Exception:
            await asyncio.sleep(1)

# ✅ 用框架内置的 retries
@agent.tool(retries=3)
async def unstable_api(ctx: RunContext) -> str:
    return await call_api()
```

框架的 retries 机制会在失败时自动触发 `ModelRetry`，LLM 能感知到重试并调整参数。

### ModelRetry：让 LLM 自动修正

当工具发现参数无效时，抛出 `ModelRetry` 而不是返回错误字符串：

```python
# ❌ 返回错误字符串 — LLM 行为不确定
if not found:
    return "技能不存在"

# ✅ ModelRetry — 框架让 LLM 自动重试
from pydantic_ai import ModelRetry

if not found:
    raise ModelRetry(
        f"技能 '{name}' 不存在。可用: {available}。请调用 list_skills 后重试。"
    )
```

ModelRetry 把错误信息注入对话历史，LLM 在下一轮迭代中读到并自动修正调用参数——用户无感。

## 6. Agent 为什么默认无状态

> **本章目标**：理解 Agent 无状态设计的原理和多轮对话的实现方式
> **预计时间**：3 分钟

pydantic-ai 的 Agent 是无状态的——每次 `run()` 或 `run_stream()` 是独立的调用。这意味着：

```python
# 每次调用都是"新对话"
await agent.run("天气怎么样")
await agent.run("那明天呢")  # Agent 不知道"那"指什么
```

要实现多轮对话，需要自己管理消息历史：

```
User: "北京三日游"
  → Agent.run_stream(user_msg, message_history=[])
  → [Agent 回复 + Tool 调用] 存入 message_history

User: "加点亲子景点"
  → Agent.run_stream(user_msg, message_history=[之前的全部消息])
  → 继续存入...

User: "导出 PDF"
  → Agent.run_stream(user_msg, message_history=[...])
```

## 7. message_history：实现多轮对话

> **本章目标**：用 message_history 在代码中实现对话记忆
> **预计时间**：10 分钟

```python
import asyncio
from dataclasses import KW_ONLY, dataclass, field
from pydantic_ai import Agent
from pydantic_ai.messages import ModelMessage
from pydantic_ai.models.openai import OpenAIChatModel
from pydantic_ai.providers.openai import OpenAIProvider
from openai import AsyncOpenAI

client = AsyncOpenAI(api_key="your-api-key", base_url="https://api.deepseek.com/v1")
model = OpenAIChatModel("deepseek-chat", provider=OpenAIProvider(openai_client=client))
agent = Agent(model=model, instructions="You are a helpful assistant. Reply in Chinese.")


@dataclass
class Conversation:
    """管理多轮对话状态"""
    agent: Agent
    messages: list[ModelMessage] = field(default_factory=list)

    async def chat(self, user_input: str) -> str:
        """发送消息，返回完整回复文本"""
        full_reply = ""

        async with self.agent.run_stream(
            user_input,
            message_history=self.messages,  # ← 关键：传入历史
        ) as result:
            async for event in result.stream():
                if hasattr(event, 'delta') and event.delta:
                    print(event.delta, end='', flush=True)
                    full_reply += event.delta

        # result.new_messages() 包含了本轮的 ModelRequest 和 ModelResponse
        # 格式由框架保证，不需要手动构造
        self.messages.extend(result.new_messages())
        print()
        return full_reply


async def main():
    conv = Conversation(agent=agent)

    while True:
        try:
            user_input = input("\n你: ").strip()
            if user_input.lower() in ("exit", "quit", "q"):
                break
            print("AI: ", end="")
            await conv.chat(user_input)
        except KeyboardInterrupt:
            break


asyncio.run(main())
```

## 8. result.new_messages() 的正确用法

> **本章目标**：掌握 `result.new_messages()` 的正确使用方式
> **预计时间**：5 分钟

前面示例中手拼了 `ModelRequest` 和 `ModelResponse`。更好的做法是直接从 `result` 获取消息：

```python
# ❌ 不要自己构建 ModelMessage 的底层数据结构
messages.append({"role": "user", "content": "hello"})  # 格式可能和框架不一致

# ✅ 用 run_stream 返回的 result.new_messages()
messages = []

async with agent.run_stream(user_input, message_history=messages) as result:
    async for event in result.stream():
        ...

messages.extend(result.new_messages())  # 框架保证格式正确
```

`result.new_messages()` 返回本轮自动生成的完整消息列表（包括 assistant 消息、工具调用消息、工具结果等），格式由框架保证。

修正后的 `Conversation.chat()`：

```python
async def chat(self, user_input: str) -> str:
    full_reply = ""

    async with self.agent.run_stream(
        user_input,
        message_history=self.messages,
    ) as result:
        async for event in result.stream():
            if hasattr(event, 'delta') and event.delta:
                print(event.delta, end='', flush=True)
                full_reply += event.delta

    # ✅ 使用 new_messages() 追加
    self.messages.extend(result.new_messages())
    print()
    return full_reply
```

## 9. Loop Agent：自动续跑

> **本章目标**：理解并实现 token 超限时的自动续跑机制
> **预计时间**：8 分钟

当对话 token 超过 LLM 的上下文限制时，`UsageLimitExceeded` 会被触发。自动续跑解决这个问题：

```python
from pydantic_ai.usage import UsageLimits


async def chat_with_continue(conv: Conversation, user_input: str):
    """带自动续跑的对话"""
    max_continues = 2  # 最多续跑 2 次
    continue_count = 0

    while True:
        try:
            full_reply = ""
            async with conv.agent.run_stream(
                user_input if continue_count == 0 else "继续",
                message_history=conv.messages,
                usage_limits=UsageLimits(
                    request_limit=50,           # 最多 50 个请求
                    total_tokens_limit=100_000,  # 总 token 上限
                ),
            ) as result:
                async for event in result.stream():
                    if hasattr(event, 'delta') and event.delta:
                        print(event.delta, end='', flush=True)
                        full_reply += event.delta

            # 正常完成，追加到历史
            conv.messages.extend(result.new_messages())
            print()
            return full_reply

        except Exception as e:
            if "UsageLimitExceeded" in str(type(e).__name__):
                continue_count += 1
                if continue_count > max_continues:
                    print("\n[已达到最大续跑次数]")
                    raise
                print(f"\n[续跑 {continue_count}/{max_continues}...]")
                # 框架已经把部分响应写入了 message_history
                # 不需要手动拼接，直接让 Agent 继续
                user_input = "继续执行未完成的任务"
            else:
                raise
```

## 常见错误

1. **异常类型判断用字符串匹配**：`"UsageLimitExceeded" in str(type(e).__name__)` 脆弱，应改用 `isinstance` 或导入异常类
2. **续跑次数无上限**：不加 `max_continues` 可能导致无限续跑和无限 token 消耗

## 10. UsageLimits：成本控制

> **本章目标**：用 UsageLimits 保护 API 额度，防止无限 token 消耗
> **预计时间**：5 分钟

`UsageLimits` 是安全阀——不是性能优化，是成本控制。

```python
from pydantic_ai.usage import UsageLimits

# 严格的限制
strict_limits = UsageLimits(
    request_limit=10,            # 最多 10 个请求（包括工具调用）
    total_tokens_limit=10_000,   # 总 token 不超过 1 万
)

# 宽松的限制
relaxed_limits = UsageLimits(
    request_limit=100,
    total_tokens_limit=100_000,
)

async def main():
    result = await agent.run(
        "写一篇长篇故事",
        usage_limits=UsageLimits(
            request_limit=50,
            total_tokens_limit=50_000,
        ),
    )
    print(result.data)
```

没有 token 限制时，长对话可能耗尽 API 额度。建议：
- 生产环境：设 `total_tokens_limit` 为预期的 2 倍
- 开发环境：设一个较小的值（如 5000），快速发现问题
