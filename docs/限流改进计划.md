下面是**完整、详细、可执行的限流改进计划**。
它基于你当前的 `integrated-no-backend` 版本，并采用刚才审查后的稳妥方案：**保留 SlowAPI，增加全局默认限流，支持可选 Redis 存储，给 login/refresh 补真正的装饰器，不做用户维度、不做 Tier、不做 AI token quota**。

SlowAPI 官方文档确认支持 `default_limits` 作为全局默认限流，也支持 `storage_uri` 接 Redis；同时文档要求被 `@limiter.limit()` 装饰的 endpoint 必须显式包含 `request: Request`，并且 FastAPI route decorator 要写在 `@limiter.limit()` 上方。([slowapi.readthedocs.io][1])

# 限流改进执行计划 v1

## 一、目标

本次只做轻量增强：

```text
1. 给所有未单独装饰的接口加全局默认限流
2. login / refresh 保持更严格的单独限流
3. 支持生产环境使用 Redis 作为限流存储
4. 开发 / 测试环境默认继续使用内存存储
5. 不新增依赖
6. 不做逐端点精细限流
7. 不做用户维度限流
8. 不做 API Key / Tier / token quota
```

最终效果：

| 端点                          | 限流                    |
| --------------------------- | --------------------- |
| `POST /api/v1/auth/login`   | `5/minute`            |
| `POST /api/v1/auth/refresh` | `10/minute`           |
| 其他所有端点                      | `200/day` + `50/hour` |
| 配置了 Redis storage           | 多 worker / 多实例共享计数    |
| 未配置 Redis storage           | 内存限流，适合开发和测试          |

# 二、关键设计决定

## 1. 不直接复用 `REDIS_URL`

不建议用：

```python
_storage_uri = settings.REDIS_URL or None
```

原因是当前项目里的 `REDIS_URL` 可能用于缓存、消息、其他 Redis 功能；而且如果默认值是 `redis://localhost:6379/0`，开发环境没有 Redis 时会导致限流模块默认尝试连 Redis。

所以新增独立配置：

```python
RATE_LIMIT_STORAGE_URL: str = ""
```

含义：

```text
空字符串：使用内存限流
redis://...：使用 Redis 限流存储
```

这样不会影响其他 Redis 功能。

---

## 2. 默认限流配置用字符串，但代码里 split 成列表

配置写成：

```python
RATE_LIMIT_DEFAULT: str = "200/day,50/hour"
```

代码转换成：

```python
["200/day", "50/hour"]
```

原因是 SlowAPI 的 `default_limits` 参数是“一组 limit 字符串或 callable”，所以传列表更稳。([slowapi.readthedocs.io][2])

---

## 3. 开启内存 fallback

生产环境 Redis 短暂不可用时，不希望整个 API 被限流组件拖死。
所以加：

```python
in_memory_fallback_enabled=True
```

官方 API reference 说明这个参数会在主存储不可用时 fallback 到内存存储，并继承原来的 limits。([slowapi.readthedocs.io][2])

# Step 2：重写 `src/core/rate_limit.py`

打开：

```text
src/core/rate_limit.py
```

把当前内容：

```python
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)
```

替换为：

```python
from slowapi import Limiter
from slowapi.util import get_remote_address

from core.config import settings


_default_limits = [
    item.strip()
    for item in settings.RATE_LIMIT_DEFAULT.split(",")
    if item.strip()
]

limiter_kwargs = {
    "key_func": get_remote_address,
    "default_limits": _default_limits,
    "in_memory_fallback_enabled": True,
}

if settings.RATE_LIMIT_STORAGE_URL:
    limiter_kwargs["storage_uri"] = settings.RATE_LIMIT_STORAGE_URL

limiter = Limiter(**limiter_kwargs)
```

这一版的行为：

```text
RATE_LIMIT_STORAGE_URL 为空 → 内存模式
RATE_LIMIT_STORAGE_URL=redis://localhost:6379/0 → Redis 模式
RATE_LIMIT_DEFAULT=200/day,50/hour → 全局默认限流为 200/day + 50/hour
Redis 挂了 → fallback 到内存模式
```

# Step 3：确认 `init_app.py` 已正确接入 SlowAPI

打开：

```text
src/core/init_app.py
```

确认有类似逻辑：

```python
from slowapi import _rate_limit_exceeded_handler
from slowapi.errors import RateLimitExceeded
from slowapi.middleware import SlowAPIMiddleware

from core.rate_limit import limiter
```

并确认 app 初始化时有：

```python
app.state.limiter = limiter
app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)
app.add_middleware(SlowAPIMiddleware)
```

如果没有，就补上。

建议整理成类似：

```python
def init_rate_limit(app: FastAPI) -> None:
    app.state.limiter = limiter
    app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)
    app.add_middleware(SlowAPIMiddleware)
```

然后在 `init_app(app)` 或你的 app 初始化函数里调用：

```python
init_rate_limit(app)
```

注意：

```text
如果当前项目已经有这段逻辑，不要重复 add_middleware。
```

SlowAPI 文档里的全局默认限流示例就是 `Limiter(default_limits=[...])` + `app.state.limiter` + `RateLimitExceeded handler` + `SlowAPIMiddleware` 组合。([slowapi.readthedocs.io][1])

## 4.1 修改 login endpoint

找到 login endpoint，大概率类似：

```python
@router.post("/login", summary="登录获取 token")
async def login_access_token(
    request: Request,
    credentials: CredentialsSchema,
    db: AsyncSession = Depends(get_db),
):
    ...
```

改成：

```python
@router.post("/login", summary="登录获取 token")
@limiter.limit("5/minute")
async def login_access_token(
    request: Request,
    credentials: CredentialsSchema,
    db: AsyncSession = Depends(get_db),
):
    ...
```

注意装饰器顺序必须是：

```python
@router.post(...)
@limiter.limit(...)
async def ...
```

不要写反。SlowAPI 文档明确说明 FastAPI route decorator 必须在 `@limiter.limit()` 上面。([slowapi.readthedocs.io][3])

---

## 4.2 修改 refresh endpoint

找到 refresh endpoint，大概率类似：

```python
async def refresh_access_token(
    request: Request,
    refresh_request: RefreshTokenRequest,
    db: AsyncSession = Depends(get_db),
):
    ...
```

改成：

```python
@router.post("/refresh", summary="刷新 token")
```

## 4.3 删除无用的包装函数

如果当前 `auth.py` 里有这个但没有实际使用：

```python
def apply_rate_limit(rate: str = "5/minute"):
    def decorator(func):
        return limiter.limit(rate)(func)
    return decorator
```

建议删除。
保留直接的：

```python
@limiter.limit("5/minute")
```

更清楚，也符合 SlowAPI 文档示例。

## 方案 A：只测 login 装饰器触发 429

这个最简单，不改 app 初始化。

新增：

```python
import pytest


@pytest.mark.asyncio
async def test_login_rate_limit(client):
    payload = {
        "username": "wrong-user",
        "password": "wrong-password",
    }

    status_codes = []

    for _ in range(7):
        response = await client.post("/api/v1/auth/login", json=payload)
        status_codes.append(response.status_code)

    assert 429 in status_codes
```

问题：如果测试 client 里限流被全局 disabled，就不会触发。
如果当前测试为了稳定禁用了 limiter，这个测试要单独启用。

---

## 方案 B：新增一个测试专用 endpoint，更可控

如果测试架构允许临时往 app 加 route，可以这样：

```python
from fastapi import Request

from core.rate_limit import limiter


def test_global_rate_limit_smoke(app, client):
    @app.get("/__test_rate_limit")
    async def test_rate_limited_endpoint(request: Request):
        return {"ok": True}

    # 这里只能验证 default_limits 已挂到 app，
    # 不建议真的用 200/day 去压测。
    response = client.get("/__test_rate_limit")
    assert response.status_code in {200, 429}
```

这个测试价值较低，只能验证不崩。

# 六、风险点和处理方式

## 风险 1：测试被限流影响

如果 `pytest` 里大量请求同一个 endpoint，可能出现 429。

处理方式：

```text
1. 测试环境设置 RATE_LIMIT_DEFAULT=100000/day
2. 或者测试环境禁用 limiter
3. 或者只对专门的 rate limit 测试启用低阈值
```

如果要支持测试环境禁用，可以后续加：

```python
RATE_LIMIT_ENABLED: bool = True
```

然后：

```python
limiter_kwargs = {
    "key_func": get_remote_address,
    "default_limits": _default_limits,
    "enabled": settings.RATE_LIMIT_ENABLED,
    "in_memory_fallback_enabled": True,
}
```

本轮不是必须。

---

## 风险 2：Redis 不可用

已通过：

```python
in_memory_fallback_enabled=True
```

降低风险。

---

## 风险 3：反向代理下 IP 不准确

`get_remote_address` 取到的可能是反向代理 IP，而不是用户真实 IP。
本轮不处理用户维度 key，也不处理复杂代理头。后续生产部署时再统一处理：

```text
Nginx / Traefik / Cloudflare / Uvicorn ProxyHeadersMiddleware
```

SlowAPI API reference 也说明 `get_remote_address` 返回当前 request 的 IP，而 `get_ipaddr` 会考虑 `X-Forwarded-For`，但更稳的代理处理应放在部署层。([slowapi.readthedocs.io][2])
