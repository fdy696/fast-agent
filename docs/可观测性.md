## 模块 0：热身 — 大白话讲透"可观测性"

### 第一性原理提问

你请了一位超级聪明的"数字员工"（AI Agent），但你既看不见他在干什么，也不知道他什么时候会犯错——你敢把重要任务交给他吗？

**可观测性就是给这个"数字员工"装上监控摄像头、工作日志、心跳检测仪**，让你能回答三个问题：

| 问题 | 对应工具 | 类比 |
|------|----------|------|
| 他刚才在干嘛？ | **日志（Logging）** | 监控录像回放 |
| 他最近工作效率怎么样？ | **指标（Metrics）** | 仪表盘实时读数 |
| 一个复杂任务从头到尾怎么完成的？ | **追踪（Tracing）** | 任务流程图 |

### 传统后端 vs AI Agent 的差异

传统后端只需观测 HTTP 请求/响应、数据库查询、服务间调用。AI Agent 在这些之上，**必须增加**：

- 模型调用链（每次 LLM API 请求的完整信息）
- Token 消耗（输入/输出 token，直接影响成本）
- 工具调用（Function Calling 的成功/失败/耗时）
- 推理步骤回溯（Agent 思考→行动→观察的每一步）
- 回答质量（答案是否正确，而不只是"是否返回了"）

### 企业实际痛点

1. "用户说回答错了，我翻遍服务器日志也找不到 Agent 当时的完整思考路径。"
2. "月底一看账单，Token 费用超预算 3 倍，到底哪个环节在烧钱？"
3. "Agent 随机调用了一个挂掉的 API 工具，服务异常半小时才发现。"

### fast-agent 的三层可观测架构

```
┌─────────────────────────────────────────────────┐
│  第一层：聚合指标 (Prometheus)                     │
│  看整体：QPS / P99延迟 / 错误率 / Token消耗趋势     │
├─────────────────────────────────────────────────┤
│  第二层：调用追踪 (Langfuse + OpenTelemetry)       │
│  看每次调用：模型参数 / token / 耗时 / 费用 / 工具链  │
├─────────────────────────────────────────────────┤
│  第三层：上下文日志 (Loguru + trace_id)              │
│  看单次请求完整日志链：从 HTTP 到 Agent 决策         │
└─────────────────────────────────────────────────┘
```

## 模块 1：观测维度 — AI Agent 到底要观测什么

### 是什么

观测维度 = 出问题时"你最想第一时间知道的那些数据"，从故障回溯反推而来。

### 核心观测对象

```
1. LLM 调用
   ├── 请求/响应内容
   ├── 延迟（首 Token 时间、总时间）
   ├── Token 消耗（输入/输出/总计）
   ├── 模型名称、温度等参数
   └── 状态码、错误信息

2. 工具调用（Function Calling / MCP）
   ├── 工具名称、输入参数、返回结果
   ├── 是否成功、耗时
   └── 来源（本地工具 / MCP 服务器名）

3. Agent 决策循环
   ├── 推理步骤（Thought → Action → Observation）
   ├── 每一步的时间戳与顺序
   ├── 激活了哪些 Skill
   └── 最终答案生成路径

4. 会话 & 用户
   ├── trace_id / session_id / user_id
   ├── 对话轮次
   └── 用户反馈（点赞/点踩）

5. 资源 & 成本
   ├── 单次调用费用估算
   └── 时间段内总 Token / 费用
```

### 数据模型定义

这是整个可观测系统的"数据底座"，所有后续模块都基于它：

```python
# 文件: src/agent/trace_data.py
from dataclasses import dataclass, field, asdict
from typing import Any, Optional
from datetime import datetime, timezone
import uuid


def _now_iso() -> str:
    return datetime.now(timezone.utc).isoformat()


def _short_id() -> str:
    return uuid.uuid4().hex[:8]


@dataclass
class LLMCallRecord:
    """一次 LLM 调用的完整记录"""
    call_id: str = field(default_factory=_short_id)
    timestamp: str = field(default_factory=_now_iso)
    model: str = ""
    provider: str = ""          # dashscope / deepseek
    temperature: float = 0.2
    max_tokens: int = 0
    # 性能
    time_to_first_token_ms: float = 0.0
    total_time_ms: float = 0.0
    # Token
    input_tokens: int = 0
    output_tokens: int = 0
    # 内容摘要（不存完整内容，太大）
    input_summary: str = ""     # 用户问题摘要
    output_summary: str = ""    # 模型回复摘要
    # 状态
    success: bool = True
    error_message: str = ""
    retry_count: int = 0


@dataclass
class ToolCallRecord:
    """一次工具调用的完整记录"""
    call_id: str = field(default_factory=_short_id)
    timestamp: str = field(default_factory=_now_iso)
    tool_name: str = ""
    source: str = ""            # "local" | "mcp:<server_name>"
    input_params: dict = field(default_factory=dict)
    output_summary: str = ""    # 摘要而非完整结果
    duration_ms: float = 0.0
    success: bool = True
    error_message: str = ""


@dataclass
class AgentTrace:
    """一次 Agent 完整交互的追踪"""
    trace_id: str = field(default_factory=lambda: uuid.uuid4().hex[:16])
    session_id: str = ""
    user_id: str = ""
    start_time: str = field(default_factory=_now_iso)
    end_time: str = ""
    # 调用链
    llm_calls: list[LLMCallRecord] = field(default_factory=list)
    tool_calls: list[ToolCallRecord] = field(default_factory=list)
    # Agent 特有
    active_skills: list[str] = field(default_factory=list)
    loop_count: int = 0
    # 结果
    final_answer_summary: str = ""
    total_tokens: int = 0
    estimated_cost_usd: float = 0.0
    user_feedback: Optional[str] = None

    def to_dict(self) -> dict:
        return asdict(self)
```

## 模块 2：结构化日志 — trace_id 贯穿全链路

### 是什么

给每条日志自动打上 `trace_id`、`request_id`、`user_id`、`session_id`，让分散在各个文件里的日志能被串联成一次完整请求的"时间线"。

### 当前项目已有的基础

你的 `src/log/context.py` 已经用 `contextvars` 实现了请求级别的上下文隔离：

```python
# 已有: src/log/context.py
request_id_var: ContextVar[str] = ContextVar("request_id", default="-")
user_id_var: ContextVar[str] = ContextVar("user_id", default="-")
```

`contextvars` 是解决并发安全的关键 —— 每个协程有自己独立的上下文副本，不同请求的 `request_id` 不会互相覆盖。这是大纲模块 2 的 `AgentTracer` 缺少的东西。

### 优化目标

当前日志格式是彩色的、给人看的。生产环境需要：

- JSON 格式输出（方便 ELK/Loki 采集）
- 自动带 `trace_id` / `session_id`
- Agent 循环内的日志也能关联到同一个 trace

### 改造 `src/log/log.py`

```python
# 文件: src/log/log.py（改造后）
import os
import sys
import json
from datetime import datetime, timezone

from loguru import logger as loguru_logger

from core.config import settings
from log.context import LogContext


def _json_formatter(record: dict) -> str:
    """生产环境 JSON 格式，自动注入 trace 上下文"""
    log_entry = {
        "timestamp": record["time"].strftime("%Y-%m-%dT%H:%M:%S.%f")[:-3] + "Z",
        "level": record["level"].name,
        "logger": record["name"],
        "function": record["function"],
        "line": record["line"],
        "message": record["message"],
        "request_id": LogContext.get_request_id(),
        "user_id": LogContext.get_user_id(),
        "trace_id": getattr(record["extra"], "trace_id", "-"),
        "session_id": getattr(record["extra"], "session_id", "-"),
    }
    if record["exception"]:
        log_entry["exception"] = str(record["exception"])
    return json.dumps(log_entry, ensure_ascii=False, default=str) + "\n"


class LoggingConfig:
    def __init__(self):
        self.debug = settings.DEBUG
        self.level = "DEBUG" if self.debug else "INFO"
        self.log_dir = "logs"
        os.makedirs(self.log_dir, exist_ok=True)

    def setup_logger(self):
        loguru_logger.remove()

        # 开发环境：彩色控制台
        if settings.APP_ENV == "development":
            loguru_logger.add(
                sys.stdout,
                level=self.level,
                format=(
                    "<green>{time:HH:mm:ss.SSS}</green> | "
                    "<level>{level: <8}</level> | "
                    "<cyan>{extra[request_id]}</cyan> | "
                    "<level>{message}</level>"
                ),
                colorize=True,
                backtrace=True,
                diagnose=True,
            )

        # 生产环境：JSON 格式文件
        loguru_logger.add(
            f"{self.log_dir}/app_{{time:YYYY-MM-DD}}.log",
            level="INFO",
            format=_json_formatter,  # 注意：传函数引用，不是字符串
            rotation="100 MB",
            retention="30 days",
            compression="zip",
            encoding="utf-8",
            serialize=False,  # 我们自己控制 JSON 格式
        )
        loguru_logger.add(
            f"{self.log_dir}/error_{{time:YYYY-MM-DD}}.log",
            level="ERROR",
            format=_json_formatter,
            rotation="50 MB",
            retention="90 days",
            compression="zip",
            encoding="utf-8",
        )

        return loguru_logger


logging_config = LoggingConfig()
logger = logging_config.setup_logger()
```

> **注意**：Loguru 的 `format` 参数直接传函数时，必须用 `logger.add(..., format=func)` 而非 `format="..."`。但 Loguru 的 `format` 参数接受 callable 需要特定签名。实际上更简单的做法是用 `patcher`：

```python
# 更简单的方案：用 patcher 注入上下文
def _patch_record(record):
    record["extra"]["request_id"] = LogContext.get_request_id()
    record["extra"]["user_id"] = LogContext.get_user_id()

loguru_logger.configure(patcher=_patch_record)
```

### 中间件：自动注入 trace 上下文

新增一个中间件，在请求入口设置 trace 上下文，出口清理：

```python
# 文件: src/core/middlewares.py（新增中间件）

class TraceContextMiddleware(BaseHTTPMiddleware):
    """每次 HTTP 请求自动生成 trace_id，注入日志上下文"""

    async def dispatch(
        self, request: Request, call_next: RequestResponseEndpoint
    ) -> Response:
        # 入口：生成 trace_id
        trace_id = request.headers.get("X-Trace-Id", uuid.uuid4().hex[:16])
        LogContext.set_request_id(trace_id)

        # 尝试从 JWT 解出 user_id
        auth = request.headers.get("Authorization", "")
        if auth.startswith("Bearer "):
            try:
                payload = verify_token(
                    auth.removeprefix("Bearer ").strip(), token_type="access"
                )
                LogContext.set_user_id(str(payload.get("user_id", "-")))
            except Exception:
                pass

        try:
            response = await call_next(request)
            response.headers["X-Trace-Id"] = trace_id
            return response
        finally:
            LogContext.clear()
```

### 中间件顺序（重要）

在 `src/core/init_app.py` 的 `make_middlewares()` 中，`TraceContextMiddleware` 必须排第一：

```python
def make_middlewares() -> list[Middleware]:
    return [
        Middleware(TraceContextMiddleware),       # ← 第一：注入 trace 上下文
        Middleware(
            CORSMiddleware,
            allow_origins=settings.CORS_ORIGINS_LIST,
            allow_credentials=settings.CORS_ALLOW_CREDENTIALS,
            allow_methods=settings.CORS_ALLOW_METHODS,
            allow_headers=settings.CORS_ALLOW_HEADERS,
        ),
        Middleware(MetricsMiddleware),            # ← 第二：记录 HTTP 指标
        Middleware(RequestLoggingMiddleware),
        Middleware(HttpAuditLogMiddleware, ...),
        Middleware(SlowAPIMiddleware),
    ]
```

## 模块 3：LLM 调用追踪 — Langfuse 零侵入接入

### 是什么

Langfuse 是 LLM 可观测领域的专用工具。和 OpenTelemetry 的关系是：

| 维度 | OpenTelemetry | Langfuse |
|------|---------------|----------|
| 定位 | 通用分布式追踪标准 | LLM 专用可观测平台 |
| LLM 感知 | 无（需手动打 Span） | 内置（自动记录 model/token/cost） |
| Token 计费 | 自己算 | 自动 |
| 评估 | 无 | 内置 LLM-as-Judge |
| 部署 | 自建（Jaeger/Zipkin） | SaaS 或自建 |

**我们的策略**：Langfuse 做 LLM 调用追踪（开箱即用），OpenTelemetry 做跨服务追踪（模块 5），两者互补。

### Langfuse 工作原理

```
你的代码
  │
  ▼
langfuse.openai.AsyncOpenAI  ← 替换 openai.AsyncOpenAI
  │
  ├──▶ OpenAI / DashScope API（正常请求）
  │
  └──▶ Langfuse 后端（异步上报：model, tokens, latency, cost, success）
```

对 OpenAI 兼容协议的服务（DashScope、DeepSeek 等），**一行 import 替换**就能自动追踪。

from log import logger

# ── Langfuse 可选接入 ──

    try:
        from langfuse.openai import AsyncOpenAI as LangfuseAsyncOpenAI
        _ClientClass = LangfuseAsyncOpenAI
        _langfuse_enabled = True
        logger.info("Langfuse tracing enabled")
    except ImportError:
        logger.warning("langfuse 未安装，回退到标准 OpenAI 客户端")

_client: AsyncOpenAI | None = None


def _get_client() -> AsyncOpenAI:

    if _client is None:
        _client = _ClientClass(
            api_key=settings.API_KEY or "dummy",
            base_url=settings.AGENT_BASE_URL,
        )
    return _client


async def call_model(
    messages: Iterable[ChatCompletionMessageParam],
    tools: Iterable[ChatCompletionToolUnionParam],
    response_format: Literal["text", "json_object"],
    stream: bool = True,
    tool_choice: Literal["auto", "none"] = "auto",
    enable_thinking: bool = False,
    model: str = "",

        model=model or settings.AGENT_MODEL,
        messages=messages,
        tools=tools,
        stream=stream,
        temperature=0.2,
        response_format=cast(Any, {"type": response_format}),
        tool_choice=tool_choice,
        extra_body={"enable_thinking": enable_thinking},
    )


async def call_compress_model(
    messages: Iterable[ChatCompletionMessageParam],
) -> Any:
    return await _get_client().chat.completions.create(
        model=settings.COMPRESS_MODEL,
        stream=False,
        messages=messages,
        extra_body={"thinking": {"type": "disabled"}},

### 自定义 Trace：关联 Agent 上下文

Langfuse 自动追踪每次 LLM 调用，但我们还想关联 session_id、user_id、Agent 步骤。

```python
# 文件: src/agent/trace_context.py（新建）
"""Langfuse trace 上下文管理器"""

import os
from contextvars import ContextVar
from typing import Optional


_langfuse_trace_var: ContextVar[Optional[dict]] = ContextVar(
    "langfuse_trace", default=None
)


class AgentTraceContext:
    """在 Agent 循环中创建 Langfuse trace，关联 session/user"""

    @staticmethod
    def start(
        session_id: str,
        user_id: str,
        metadata: Optional[dict] = None,
    ) -> None:
        """开始一次 Agent trace"""
        if os.getenv("LANGFUSE_TRACING_ENABLED", "").lower() != "true":
            return

        try:
            from langfuse import get_client
            trace = get_client().trace(
                name="agent-execution",
                session_id=session_id,
                user_id=str(user_id),
                metadata=metadata or {},
            )
            _langfuse_trace_var.set({"trace": trace, "step": 0})
        except Exception:
            pass

    @staticmethod
    def log_step(step_type: str, input_data: str, output_data: str) -> None:
        """记录一个 Agent 步骤（思考/工具调用/观察）"""
        ctx = _langfuse_trace_var.get()
        if ctx is None:
            return
        ctx["step"] += 1
        try:
            ctx["trace"].span(
                name=f"step-{ctx['step']}-{step_type}",
                input=input_data[:500],
                output=output_data[:500],
            )
        except Exception:
            pass

    @staticmethod
    def end(final_output: str, total_tokens: int) -> None:
        """结束 trace"""
        ctx = _langfuse_trace_var.get()
        if ctx is None:
            return
        try:
            ctx["trace"].update(
                output=final_output[:1000],
                metadata={"total_tokens": total_tokens},
            )
        except Exception:
            pass

class MetricsMiddleware:
    """记录 HTTP 请求指标（纯 ASGI 中间件，不依赖 BaseHTTPMiddleware）"""

    def __init__(self, app):
        self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return

        import time
        start = time.time()
        status_code = 500

        async def _send(message):
            nonlocal status_code
            if message["type"] == "http.response.start":
                status_code = message["status"]
            await send(message)

        try:
            await self.app(scope, receive, _send)
        finally:
            duration = time.time() - start
            endpoint = scope.get("route", {}).get("path", scope["path"])
            method = scope["method"]
            http_requests_total.labels(
                method=method, endpoint=endpoint, status=str(status_code)
            ).inc()
            http_request_duration_seconds.labels(
                method=method, endpoint=endpoint
            ).observe(duration)

## 模块 5：全链路追踪 — OpenTelemetry 分布式 Span

### 是什么

OpenTelemetry（OTel）是 CNCF 的追踪标准。当 Agent 调用拆分成多个微服务、或通过 MCP 调用外部工具 API 时，OTel 能还原完整调用链瀑布图。

### 和 Langfuse 的分工

```
Langfuse：LLM 调用粒度（model, token, cost, prompt）
OpenTelemetry：服务间调用粒度（HTTP → Agent → MCP → DB）
两者互补，不是替代关系。
```

### 接入实现

```python
# 文件: src/core/tracing.py（新建）
"""OpenTelemetry 初始化与 Span 工具"""

import os
from contextlib import asynccontextmanager
from typing import AsyncIterator

from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.sdk.resources import Resource
from opentelemetry.exporter.otlp.proto.http.trace_exporter import (
    OTLPSpanExporter,
)
from opentelemetry.instrumentation.fastapi import FastAPIInstrumentor
from opentelemetry.instrumentation.httpx import HTTPXClientInstrumentor
from fastapi import FastAPI

from core.config import settings

_tracer: trace.Tracer | None = None


def setup_tracing(app: FastAPI) -> None:
    """在 create_app() 中调用，初始化 OTel"""
    otel_endpoint = os.getenv("OTEL_EXPORTER_OTLP_ENDPOINT", "")
    if not otel_endpoint:
        return  # 未配置则不启用

    resource = Resource.create({
        "service.name": settings.APP_TITLE,
        "service.version": settings.VERSION,
    })

    provider = TracerProvider(resource=resource)
    exporter = OTLPSpanExporter(endpoint=f"{otel_endpoint}/v1/traces")
    provider.add_span_processor(BatchSpanProcessor(exporter))
    trace.set_tracer_provider(provider)

    # 自动打点：FastAPI + httpx
    FastAPIInstrumentor.instrument_app(app)
    HTTPXClientInstrumentor().instrument()

    global _tracer
    _tracer = trace.get_tracer(__name__)
    from log import logger
    logger.info(f"OpenTelemetry tracing enabled → {otel_endpoint}")


def get_tracer() -> trace.Tracer:
    return _tracer or trace.get_tracer(__name__)


@asynccontextmanager
async def traced_span(
    name: str,
    attributes: dict | None = None,
) -> AsyncIterator[None]:
    """在 Agent 循环中手动创建 Span 的便捷上下文管理器"""
    tracer = get_tracer()
    with tracer.start_as_current_span(name) as span:
        if attributes:
            span.set_attributes(attributes)
        try:
            yield
        except Exception as e:
            span.set_attribute("error", True)
            span.set_attribute("error.message", str(e))
            raise
```

## 模块 6：LLM 弹性 — 降级 + 重试 + 健康检测

### 是什么

LLM API 不是 100% 可用的。生产环境需要：
- **重试**：临时网络抖动自动重试
- **降级**：主模型挂了切备用模型
- **健康检测**：主动探测，而不是等用户报错才发现

### 降级链路设计

```
第一层：qwen3.7-max → tenacity 指数退避 (2s → 4s → 8s) → 超时 30s
   ↓ 失败
第二层：deepseek-v4-flash → 同样 retry + timeout
   ↓ 失败
第三层：静态兜底 "服务暂时繁忙，请稍后重试"
```

### 改造 `src/agent/model_client.py`

```python
# 文件: src/agent/model_client.py（增加降级逻辑）
import asyncio
from tenacity import (
    retry, stop_after_attempt, wait_exponential, retry_if_exception_type,
)

from core.metrics import llm_failover_total, llm_requests_total

# 模型降级链
FALLBACK_CHAIN = [
    {"model": "qwen3.7-max",      "base_url": "https://dashscope.aliyuncs.com/compatible-mode/v1"},
    {"model": "deepseek-v4-flash", "base_url": "https://api.deepseek.com/v1"},
]

STATIC_FALLBACK = "抱歉，AI 服务暂时繁忙，请稍后重试。您也可以直接描述您的需求，我会尽力帮助您。"


async def call_model_with_fallback(
    messages,
    tools,
    response_format,
    stream=True,
    tool_choice="auto",
    enable_thinking=False,
) -> Any:
    """带降级的模型调用：逐个尝试 fallback 链，全部失败则返回静态兜底"""

    last_error: Exception | None = None

    for level, cfg in enumerate(FALLBACK_CHAIN):
        try:
            client = AsyncOpenAI(
                api_key=settings.API_KEY,
                base_url=cfg["base_url"],
                timeout=30.0,
            )

            result = await _call_with_retry(
                client, cfg["model"], messages, tools,
                response_format, stream, tool_choice, enable_thinking,
            )

            if level > 0:
                llm_failover_total.labels(
                    from_model=FALLBACK_CHAIN[0]["model"],
                    to_model=cfg["model"],
                ).inc()
                logger.warning(
                    f"LLM 降级: {FALLBACK_CHAIN[0]['model']} → {cfg['model']}"
                )

            return result

        except Exception as e:
            last_error = e
            logger.warning(f"LLM {cfg['model']} 失败: {e}")
            continue

    # 全链路失败
    llm_requests_total.labels(
        model="fallback", provider="static", status="error"
    ).inc()
    logger.error(f"LLM 全链路失败: {last_error}")

    if stream:
        # 流式场景：返回一个生成静态兜底消息的 async generator
        async def _fallback_stream():
            for char in STATIC_FALLBACK:
                yield _make_chunk(char)
                await asyncio.sleep(0.02)
        return _fallback_stream()
    else:
        return _make_static_response(STATIC_FALLBACK)


@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=2, max=8),
    retry=retry_if_exception_type((ConnectionError, TimeoutError)),
)
async def _call_with_retry(client, model, messages, tools, **kwargs):
    return await client.chat.completions.create(
        model=model, messages=messages, tools=tools, **kwargs,
    )
```

### LLM 健康检测端点

```python
# 文件: src/agent/llm_health.py（新建）
"""LLM 健康探测：对每个配置模型发最小请求，5s 超时"""

import asyncio
import time
from typing import Any

from openai import AsyncOpenAI
from core.config import settings

HEALTH_CHECK_MODELS = [
    {"model": "qwen3.7-max",      "base_url": "https://dashscope.aliyuncs.com/compatible-mode/v1"},
    {"model": "deepseek-v4-flash", "base_url": "https://api.deepseek.com/v1"},
]


async def probe_single_model(cfg: dict) -> dict[str, Any]:
    start = time.monotonic()
    try:
        client = AsyncOpenAI(
            api_key=settings.API_KEY,
            base_url=cfg["base_url"],
            timeout=5.0,
        )
        resp = await asyncio.wait_for(
            client.chat.completions.create(
                model=cfg["model"],
                messages=[{"role": "user", "content": "hi"}],
                max_tokens=1,
                stream=False,
            ),
            timeout=5.0,
        )
        latency_ms = (time.monotonic() - start) * 1000
        return {
            "model": cfg["model"],
            "provider": "dashscope" if "dashscope" in cfg["base_url"] else "deepseek",
            "healthy": True,
            "latency_ms": round(latency_ms, 1),
        }
    except Exception as e:
        return {
            "model": cfg["model"],
            "provider": "dashscope" if "dashscope" in cfg["base_url"] else "deepseek",
            "healthy": False,
            "error": str(e)[:200],
        }


async def check_all_models() -> list[dict[str, Any]]:
    results = await asyncio.gather(
        *(probe_single_model(cfg) for cfg in HEALTH_CHECK_MODELS),
        return_exceptions=True,
    )
    output = []
    for r in results:
        if isinstance(r, Exception):
            output.append({"healthy": False, "error": str(r)})
        else:
            output.append(r)
    return output
```

      - alert: MCPServerDown
        expr: mcp_connection_status == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "MCP 服务器 {{ $labels.server_name }} 断开"
          description: "MCP 服务器已断开超过 1 分钟"

      # ── Agent 循环耗尽（达到最大步数） ──
      - alert: AgentLoopExhausted

## 模块 9：回答质量 — LLM-as-Judge 评估

### 是什么

运维指标（延迟、Token、错误率）告诉你 Agent **运行是否正常**。回答质量告诉你 Agent **答案是否正确**。

这是 AI Agent 独有的观测维度，传统后端不需要关心"返回值对不对"。

### LLM-as-Judge 原理

用一个便宜、快速的模型（如 deepseek-v4-flash）充当"裁判"，对 Agent 的每次回答打分：

```python
# 文件: src/agent/quality_eval.py（新建）
"""LLM-as-Judge 回答质量评估"""

import json
import asyncio
from typing import Optional

from openai import AsyncOpenAI
from core.config import settings

EVAL_PROMPT = """你是一个回答质量评估专家。请评估以下 AI Agent 的回答质量。

用户问题：{user_question}

AI 回答：{agent_answer}

请从以下维度打分（1-5 分）：
1. 准确性：回答是否与用户问题匹配，是否包含事实错误
2. 完整性：是否覆盖了用户问题的所有方面
3. 实用性：对用户是否有实际帮助
4. 安全性：是否包含不当、危险或偏见内容

返回 JSON 格式：
{{"accuracy": 5, "completeness": 4, "usefulness": 5, "safety": 5, "overall": 4.75, "summary": "..."}}
"""


async def evaluate_answer_quality(
    user_question: str,
    agent_answer: str,
    model: str = "deepseek-v4-flash",
) -> Optional[dict]:
    """用 LLM-as-Judge 评估回答质量，返回评分 dict"""
    if not agent_answer or len(agent_answer) < 10:
        return None

    try:
        client = AsyncOpenAI(
            api_key=settings.API_KEY,
            base_url=settings.AGENT_BASE_URL,
            timeout=15.0,
        )
        resp = await client.chat.completions.create(
            model=model,
            messages=[{
                "role": "user",
                "content": EVAL_PROMPT.format(
                    user_question=user_question[:500],
                    agent_answer=agent_answer[:2000],
                ),
            }],
            temperature=0.0,
            stream=False,
        )
        content = resp.choices[0].message.content or ""
        # 提取 JSON
        content = content.strip()
        if content.startswith("```"):
            content = content.split("\n", 1)[1].rsplit("\n", 1)[0]
        return json.loads(content)
    except Exception:
        return None  # 评估失败不影响主流程


# 在 agent_loop.py 末尾添加，fire-and-forget
async def maybe_evaluate_quality(
    user_content: str,
    final_answer: str,
    session_id: str,
):
    """异步质量评估，不影响主流程"""
    result = await evaluate_answer_quality(user_content, final_answer)
    if result:
        from core.metrics import answer_quality_score
        answer_quality_score.labels(dimension="overall").observe(result["overall"])
        for dim in ["accuracy", "completeness", "usefulness", "safety"]:
            if dim in result:
                answer_quality_score.labels(dimension=dim).observe(result[dim])
```

### 新增指标

```python

    buckets=[1, 2, 3, 4, 5],
)
```

### 在 Agent 循环中集成

```python

)
